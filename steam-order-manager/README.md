# Steam Order Manager — Chrome (MV3)

Самостійне розширення **тільки для Steam buy orders**. Встановлюй цю папку, а не корінь репозиторію. Немає продажу інвентарю, relist лістингів, float-аналізу чи інших модулів.

## Встановлення

1. Завантаж публічний репозиторій (`Code → Download ZIP`) і розпакуй його.
2. Chrome → `chrome://extensions` → **Режим розробника** → **Завантажити розпаковане розширення**.
3. Вибери папку `steam-order-manager` із її власним `manifest.json`.
4. Увійди у Steam у цьому Chrome-профілі та відкрий маркет. Натисни іконку розширення.
5. Додай рядки: App ID (CS2 = 730, Dota 2 = 570), точна англійська `market_hash_name`, стан зношення, **максимальна** ціна за штуку у валюті гаманця, кількість нового ордера. Вкажи крок перевищення верхнього ордера (початково 1.00) та країну histogram (початково CZ).
6. Збережи таблицю та ввімкни **Автооновлення**. Початково воно вимкнене. Перша перевірка починається одразу, наступні — кожні N хвилин.

Назва має точно збігатися зі Steam, включно зі `StatTrak™`, `Souvenir`, символом `★` і станом зношення. Вибір зношення додає/замінює суфікс назви; якщо предмет не має зношення, вибери «Без зношення».

## Поведінка

- Немає ордера на предмет із таблиці → отримати актуальний `itemordershistogram` і створити на вказану кількість за ціною `min(макс. ціна, найвищий ордер + крок)`.
- Приклад: найнижчий лістинг 42, найвищий ордер 34, максимум 40, крок 1 → новий ордер **35**. Ціна лістинга не визначає bid: використовуються buy orders.
- Якщо верхній ордер 41, а максимум 40 — виставити по 40; лідерство не гарантоване. Якщо ордерів немає — почати з величини кроку в межах максимуму. Для дрібного кроку задай, наприклад, 0.01.
- Окремий стовпець показує три верхні **цінові рівні** ордерів у форматі `ціна × кількість` і час даних. Кількість отримується з різниць накопичувальної глибини Steam, за принципом ItemFinder.
- Залишок ≤ обраного порога (1 або 2) → скасувати, перевірити зникнення, створити на **повну** кількість із таблиці.
- Для цільової кількості 1–2 поріг обмежено `кількість − 1`, щоб цілий новий ордер не перевиставлявся нескінченно.
- Ордер із більшим залишком зберігається, але його топ-3 оновлюється при кожній перевірці. Максимум із таблиці застосовується при наступному поповненні; зміна максимуму не скасовує великий поточний ордер. Після скасування histogram запитується повторно, і нова ціна розраховується за цими свіжими даними.
- Невдалий або суперечливий histogram не використовується для створення ордера; він перевіряється ще до скасування старого ордера. Якщо другий запит після скасування не вдався, створення відкладається до наступної перевірки.
- Наявні ордери на точні предмети з активних рядків таблиці також керуються розширенням. Інші ордери не змінюються. Видалення/вимкнення рядка залишає його ордер у Steam.
- Один послідовний цикл, без паралельних створень. Для великих таблиць робота ділиться на порції з продовженням через хвилину. Налаштування, статуси й незавершені операції зберігаються у `chrome.storage.local`; таймер — `chrome.alarms`.
- Прив’язка до поточного Steam-акаунту та валюти при ввімкненні. Якщо вони змінилися, операції зупиняються. Для зміни акаунту вимкни й увімкни автооновлення після входу в потрібний Steam-акаунт.
- Steam 429 → пауза 20 хвилин. Невідомий формат списку, неповний список або помилки авторизації → жодних записів на основі такого списку.
- Якщо результат створення невідомий (розрив зв’язку, зупинка worker, підтвердження Steam), рядок блокується. Вимкни автооновлення, перевір ордери **і покупки** у Steam; потім натисни «Розблокувати». Запит міг одразу виконатися повністю, тому відсутність активного ордера не означає, що покупка не відбулася.
- Вимкнення зупиняє наступні операції. Уже відправлений Steam-запит може завершитися.

Автоматизація працює цілодобово, **поки Chrome працює, комп’ютер не спить і Steam-сесія чинна**. Таблицю можна закрити. Chrome alarms можуть затримуватися, зокрема після сну; це не серверний сервіс із точним таймером.

## Джерело та перевірка

Готове створення ордерів знайдено в `Kinatrading/slab`: `extension/background.js`, функція `runBuyFlow()` (та копія у `final extention/background.js`). Його `chrome.scripting.executeScript(world: 'MAIN')` і POST form-contract `/market/createbuyorder/` адаптовано в `steam.js`. У донорі були жорстко задані `currency: '3'` і `quantity: '1'`; тут використовується валюта поточного гаманця, кількість із таблиці й загальна сума `ціна за штуку × кількість`. HTTP 200 сам по собі більше не вважається підтвердженням створення: потрібні `success: 1` та `buy_orderid`.

Публічний `app.js` цього репозиторію: `findOrOpenSteamTab()` / `runInSteamTab()` / `steamFetch()` — основа повторного використання Steam-вкладки. Моніторинг slab, пошук дешевих лістингів, автобай-сигнали, інвентар та інші модулі не перенесено. Перевірка залишку й цикл скасування/поповнення — нова логіка.

Із ItemFinder перенесено лише принцип `buildAddedItemsOrderRequest()` / `histogramAsOrderbook()` із `app/desktop/autobuy_module/added_items_order_source.js` та базу `app/desktop/public/cs2.json` (26 573 точні назви). База знаходиться поруч із manifest, у `cs2.json`; решта ItemFinder не потрібна. `itemordershistogram` використовує `country`, `language=english`, реальну валюту поточного гаманця та `item_nameid` із бази. Для відсутнього предмета або іншої гри ID визначається з `Market_LoadOrderSpread(...)` на сторінці лістинга; якщо ID недоступний, рядок показує помилку й ордер не створюється.

Запити звірено з поточним Steam `https://community.fastly.steamstatic.com/public/javascript/market.js`: `CreateBuyOrderDialog` → `/market/createbuyorder/`; `CancelMarketBuyOrderDialog` → `/market/cancelbuyorder/`. Список читається з актуальної HTML-сторінки `/market/?l=english` у авторизованій Steam-вкладці без виконання скриптів отриманого HTML.

`npm ci && npm test` у цій папці — 32 перевірки порога, максимальної/фактичної ціни, повної кількості, histogram і топ-3, DOM-парсингу, скасування, зупинки, фонового worker й відновлення після невизначеного результату. Node/npm потрібні лише для тестів: розширення встановлюється без збірки та без npm. Реальні ордери за гроші під час розробки не створювалися. Перед цілодобовою роботою перевір один дешевий предмет у своєму акаунті: сумісність DOM зі сторінкою саме твого Steam-профілю потребує живої перевірки.
